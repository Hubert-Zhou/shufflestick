# ShuffleStick · U 盘歌单乱序助手

> 给「不支持随机播放」的设备用的歌单乱序工具。
> **免费 · 开源 (MIT) · 完全离线 · 无广告 · 无捆绑 · 绿色免安装**

适用于：车载车机、老式 MP3、蓝牙音箱、骨传导耳机、广场舞音响、电视 USB 播放……
只要它把 U 盘当 FAT32 目录遍历、又没有随机播放按钮，就可能用得上。

---

## 它解决什么问题

网上搜「U 盘歌曲播放顺序乱」，答案几乎都是**给文件名加 `01_` `02_` 序号**，
或者「按顺序一首一首剪切粘贴」。这些方法只对**按文件名字典序读盘**的固件有效。

很多廉价播放模块根本不看文件名，而是按 **FAT 目录项的物理顺序**（也就是文件
拷进 U 盘的先后）逐条遍历。这种情况下，你把名字改成什么样都无所谓，播放顺序
纹丝不动 —— 这也是「改了名还是不按顺序播」的真正原因。

本工具的做法是：**先只读诊断，判定设备到底按什么读；再对症下药改顺序。**

## 30 秒上手

1. 下载 ZIP → 解压到任意文件夹 → 双击 `ShuffleStick.exe`（无需安装、无需管理员权限）。
2. 插上要放歌的 U 盘，在窗口左上角选中对应盘符。
3. 点 **🔍 只读诊断** —— **一个字节都不会改**。报告会列出三种规则下各自的第一首。
4. 安全弹出 U 盘 → 让设备断电重连 → 听第一首是哪首，对照报告即可判定。
5. 确认这就是你要放歌的那台设备后，点 **🔗 绑定为播放设备**（一次性）。
6. 点 **▶ 执行洗牌**（打乱现有歌单）或 **📁 随机拷贝**（从电脑音频库挑一批新的进去）。

> 快捷键：`Ctrl+Enter` 执行 / `F5` 换一批 / `Ctrl+Z` 还原。

## 三种洗牌模式

| 模式 | 改的是什么 | 耗时（65 首 / 1.8 GB） | 适用 |
|---|---|---|---|
| **⚡ 极速重排**（默认） | 只重排 FAT 目录项，零字节搬运、不需备份 | **约 4 秒** | 按目录项/拷贝顺序读的设备 |
| 清盘重写 | 备份 → 删除 → 按随机序重写，连物理簇一起换 | 慢盘可达 1 小时 | 按物理簇号读、极速无效的固件 |
| 仅重命名 | 只换编号前缀和时间戳，不删文件 | 秒级 | 按文件名字典序读的设备 |

极速重排的原理：FAT 目录项是一张线性表，同盘 `rename` 只改表项、不搬数据簇。
把文件全部移进暂存目录、再按随机序列逐个移回，表的顺序就变成了随机顺序。
**耗时只跟歌曲数量线性相关，跟文件多大完全无关** —— 换成 200 首大无损也还是十几秒。

## 📁 随机拷贝

从电脑上一个很大的音频库里，每次随机挑一批拷进 U 盘：

- 支持**含子目录递归**扫描，按**容量上限**挑选（放不下的大文件自动跳过，U 盘空间不足会自动少拷）
- **尽量避开上一批**，保证「换一批」真的换了；库不够时才允许重复
- 记住上次的**源目录 / 容量 / 偏好**，下次打开直接沿用
- 写入顺序 = 目录项顺序 = 播放顺序，拷过去就是乱序的
- 每次执行前询问**替换 / 追加**；替换走「旧歌零拷贝暂存 → 新歌写入并校验 → 才删旧歌」，中途失败自动回滚

⚠️ 随机拷贝是**真搬数据**，不享受极速重排的秒级速度。界面会按保守吞吐提前估算
耗时，并在执行时显示实时 MB/s 与剩余时间。只想换顺序的话，用「⚡ 极速重排」即可。

## 安全设计

| 担心 | 处理 |
|---|---|
| 插错 U 盘，把存文件的盘洗了 | **设备白名单**：卷序列号 + 卷标 + 容量 + USB 型号，只有亲自绑定过的盘能写入 |
| 插盘就自动动手 | **不会**。插盘只弹一个提醒，所有写操作必须手动点击 + 二次确认 |
| 中途断电 / 拔盘 | 极速重排全程不删文件、可自动恢复；清盘重写先全量备份到电脑并校验 |
| 洗坏了想反悔 | **一键还原**回上一次操作之前（文件名、目录顺序、时间戳） |
| 流氓软件 | 不联网、不上传、不收集信息、无广告、无捆绑；源码 MIT 公开，可自行审阅编译 |
| 误删非音频文件 | 删除只针对扫描到的白名单音频后缀，不递归、不碰系统目录 |

配置、日志、备份都保存在程序目录下的 `shuffler_data/`（首次运行自动创建），
U 盘上不会残留任何非音频文件。

## 已知限制（请先读）

- **极速重排还差最后一次真机试听判定。** 作者设备上已验证「清盘重写」后首曲确实变化，
  但零拷贝重排只改目录项、不改物理簇位置。若你的固件按物理簇号读取，极速重排不会生效：
  请点「一键还原」后改用「清盘重写」。这也是版本号停在 **0.9.0** 而不是 1.0 的原因。
- 「随机拷贝 · 替换」删除的旧歌**不做电脑备份**，删除后无法一键还原（确认弹窗会写明）。
- 极少数设备的 FAT 实现可能不遵循「目录项顺序跟随 move」，一切以只读诊断 + 试听为准。

## 开源与自行构建

- 许可证：**MIT**，见 `LICENSE`。源码完全公开，欢迎审阅、改进、二次分发。
  **绿色包里也附了一份 `enkor_shuffler.py` 完整源码**，不联网也能自己看清楚
  这个 exe 到底会对 U 盘做什么 —— 这是开源最实在的用处。
- 源码托管：**GitHub** — https://github.com/Hubert-Zhou/shufflestick
  地址写在 `assets/repo.json`，程序每次打开「关于」页都会重新读取，
  **改这个文本文件不需要重新打包 exe**。
- 校验：发布包内附 `SHA256SUMS.txt`，下载后可用
  `Get-FileHash ShuffleStick.exe -Algorithm SHA256`（PowerShell）核对。

自己从源码构建绿色包：

```bat
pip install pyinstaller pillow
python build_release.py
```

产出 `release/ShuffleStick/`（绿色目录）与
`release/ShuffleStick-v0.9.0-win64.zip`。构建脚本**只拷贝白名单文件**，
绝不会把 `shuffler_data/`（备份、日志、还原清单）打进发布包。
刻意用 `onedir` + 关闭 UPX + 无安装包：启动快、杀软误报低、不需要管理员权限。

源码自检（不需要 U 盘）：

```bat
python enkor_shuffler.py --selftest-diagnose
python enkor_shuffler.py --selftest-copy
python enkor_shuffler.py --selftest-write
python enkor_shuffler.py --selftest-auto
python enkor_shuffler.py --fat-probe E:\
```
